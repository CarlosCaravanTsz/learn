El Component

Component
Un programa de arquitectura Elm con Model, Messages, init, update y view propios.
Evita: componente de React, submodel de Foldkit.
Model
El estado que el update de ese Component cambia, descrito con un Schema.
Evita: store, estado de la app, todo lo que la view muestra.
Message
Un hecho en pasado: algo ocurrió, y el update decide qué significa para el Model.
Evita: action, comando, setState.
init
La función pura que entrega el primer Model, y puede arrancar un Command.
Evita: constructor, useState inicial que luego se sincroniza solo.
update
La función pura que, dado el Model y un Message, entrega el Model siguiente.
Evita: reducer con efectos adentro, handler que toca el DOM.
view
La función pura que dibuja el Model. Un control no muta: construye un Message.
Evita: render con fetch, JSX que llama servicios.
props
Lo que el padre pasa al hijo. init y update lo leen en $.props; la view, en h.props.
Evita: props que el hijo copia al Model para seguirlas.
events
Lo que el hijo reporta al padre. El padre los oye en onEmit; no envuelve los Messages del hijo.
Evita: OutMessage, callback que el padre usa para mandar un Message hacia abajo.
UiSchema
El módulo de @effect/ui cuyo TaggedEnum define el union de Messages, con un constructor por tag.
Evita: enum de TypeScript, union escrita a mano.
Html
El vocabulario de elementos del host de navegador: Html.component y h.div, h.button, h.input.
Evita: JSX, el DOM como API del update.

Efectos

Command
Un efecto de una sola vuelta, descrito como valor. El runtime lo corre; el update solo lo pide con $.run.
Evita: promesa suelta, useEffect.
concurrent
El modo en que un Command nuevo corre junto al que ya va, sin cortarlo.
Evita: Promise.all escrito en la view.
switch
El modo en que un Command nuevo interrumpe la corrida anterior del mismo Command.
Evita: cancelar un fetch a mano en el update.
queue
El modo en que un Command nuevo espera a que termine el anterior, y corren en orden.
Evita: una cola propia dentro del Model.
Subscription
Un Stream con llave que corre mientras el Component lo lista. Si puedes decir «mientras…», es esto y no un Command.
Evita: setInterval, listener colgado de window dentro de update.

Servicios

service
Un contrato con nombre (Context.Service) que un Command pide. El Component no elige la implementación.
Evita: cliente HTTP importado en la view, módulo singleton.
Layer
La implementación de un service, armada para componerse. La plataforma vive en el entry; el dominio, junto al Component.
Evita: contenedor de inyección, new en init.
Component.provide
Effect.provide para un Component y lo que pinta debajo: le entrega los Layers de sus Commands.
Evita: Provider de React, pasar el service por props.
Component.lazy
Un Component cuyo módulo se carga la primera vez que se pinta, en su propio chunk.
Evita: import estático escondido, React.lazy como sinónimo en este curso.

Pruebas

En este workspace, Story, Scene y Play son tres pruebas distintas. Ninguna abre el navegador.

Story
Una prueba que manda Messages al update y mira el Model y los Commands. El Command no corre: se resuelve a mano.
Evita: test de render, mock de fetch.
Scene
Una prueba que dispara la view (clic, texto) y lee lo que se pinta. Los Commands también se resuelven a mano.
Evita: Playwright, Testing Library contra un DOM real.
Play
Una prueba que monta el Component y deja correr Commands, Subscriptions y fetches contra los Layers que el test provee.
Evita: prueba de extremo a extremo en Chrome.
