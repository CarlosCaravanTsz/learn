Comprobar el perfil que llegó

La pantalla quiere mostrar un nombre. Antes de usarlo, el programa comprueba que recibió texto.

Dos respuestas posibles

{ id: "42", name: "Ada" }
{ id: "42", name: 42 }

Supón que estas respuestas llegan de un servidor. Con la primera puedes mostrar «Ada». La segunda trae un número donde esperas texto. Una afirmación de tipo como as Profile le dice a TypeScript qué tipo quieres atribuir al dato durante la revisión del código. El valor que llegó sigue siendo 42.

Una regla que el programa sí ejecuta

const Profile = Schema.Struct({
  id: Schema.String,
  name: Schema.String,
})

const checkProfile = Schema.decodeUnknownEffect(Profile)
const program = checkProfile({ id: "42", name: 42 })

Un Schema es una regla para comprobar datos. Aquí pide texto en id y en name. checkProfile recibe el dato y devuelve un Effect, como en la lección anterior. Cuando se ejecuta, revisa los campos. Si name es 42, produce SchemaError, el nombre del fallo de validación. Introduction to Effect Schema

De dónde viene el dato

El ejemplo divide la carga en dos pasos. Primero pide el dato con source.get(id). Luego comprueba el objeto que recibió. Si falla el primer paso, se muestra RequestError. Si llega un objeto con un campo inválido, se muestra SchemaError.

Cambia un dato

Corre npm run services desde Effect/. En 02-services.ts busca name: 42 y cámbialo por name: "Lin". Predice qué se imprimirá al volver a correr el comando. El ejemplo también comprueba automáticamente la salida esperada.

Ver qué ocurre

Aparece invalid → Lin. invalid es el nombre del caso de prueba. El dato ya pasa la comprobación, así que la aserción falla porque todavía espera SchemaError. Restaura name: 42 antes de seguir. La lección siguiente usa ese dato para mostrar un error en pantalla.

Si quieres ver cómo se conecta el origen de datos

Un servicio es un conjunto de operaciones que el programa puede pedir. Aquí ProfileSource identifica el servicio que ofrece get(id). demoSource es una Layer, una forma de entregar la implementación de ese servicio. En este ejemplo entrega una función con respuestas de prueba.

Effect.provide(demoSource) conecta esa implementación a loadProfile. Si lees Effect<Profile, RequestError | SchemaError, ProfileSource>, el tercer tipo dice qué servicio falta antes de ejecutar el programa. El segundo enumera los dos fallos que espera. Managing Layers
