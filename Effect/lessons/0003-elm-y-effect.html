Del clic al nombre en pantalla

Pulsas «Cargar perfil». Ves «Cargando…». Cuando llega el perfil, ves «Ada».

El clic

Para decidir qué mostrar, guardas un valor que dice en qué estado está la pantalla. Elm llama Model a ese estado. Al pulsar el botón, la pantalla convierte el clic en un Message, un dato que registra lo que pasó. Aquí el dato es { tag: "Load", id: "42" }.

Load → update → estado Loading → vista «Cargando…»

update recibe el estado anterior y el mensaje, como un reducer de React. Devuelve el estado siguiente. view recibe ese estado y calcula qué mostrar. The Elm Architecture · React useReducer

La carga

Además de cambiar el estado a Loading, update devuelve una instrucción que pide cargar el perfil "42". Esa instrucción se llama Command. El código que coordina la aplicación recoge el Command y ejecuta el Effect que carga y comprueba el perfil.

Load → update → estado Loading → vista «Cargando…»
              → Command → ejecutar la carga

La respuesta

Al terminar la carga, el resultado vuelve como otro mensaje. Loaded trae el perfil. LoadFailed trae el motivo del fallo. update recibe ese segundo mensaje y vuelve a decidir qué mostrar.

Load   → update → estado Loading → vista «Cargando…»
                → Command → ejecutar la carga → Loaded
Loaded → update → estado Ready   → vista «Ada»

Ese recorrido se llama arquitectura Elm. Foldkit usa el mismo patrón en TypeScript y ejecuta los Commands con Effect. El ejemplo de esta lección imprime en la terminal lo que mostraría la pantalla. HTTP en Elm · Arquitectura de Foldkit

Sigue una respuesta

Antes de correr npm run elm, predice qué debería mostrar la pantalla si la última carga recibe name: 42. Busca las dos últimas líneas de salida para comprobar en qué orden aparecen los estados.

Ver qué ocurre

Primero aparece Cargando… por el mensaje Load. Luego aparece Error: SchemaError por el mensaje LoadFailed. Puedes seguir ambos mensajes en 03-elm-loop.ts.

Si llegan dos respuestas

Imagina que pides un perfil y enseguida eliges otro. Cada clic aumenta request, el número que identifica esa carga. La respuesta trae el mismo número que recibió al empezar. Si la pantalla espera la carga 2 y llega la respuesta 1, update devuelve el estado que ya tenía. El ejemplo reproduce ese orden a propósito.

Para comprobarlo, quita temporalmente || model.request !== message.request de update y corre npm run elm. El fallo de la primera carga reemplaza «Cargando…» por Error: RequestError y la comprobación del ejemplo falla. Restaura la condición después.

Si te pierdes en el recorrido, puedes traer al chat un mensaje y el estado que había justo antes de recibirlo.
