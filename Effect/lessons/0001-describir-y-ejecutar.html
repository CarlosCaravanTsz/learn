Cuándo se ejecuta un Effect

Puedes guardar una tarea y decidir después cuándo hacerla.

En JavaScript

const saludar = () => console.log("Hola")

console.log("Antes")
saludar()

La primera línea guarda una función. Primero se imprime Antes. Cuando llegas a saludar(), JavaScript entra en la función e imprime Hola.

La misma tarea con Effect

import { Effect } from "effect"

const saludar = Effect.sync(() => console.log("Hola"))

console.log("Antes")
await Effect.runPromise(saludar)

La salida es la misma. Effect.sync recibe la función y construye un Effect, un valor que describe el trabajo. Effect.runPromise ejecuta ese trabajo y devuelve una promesa. await espera a que termine. Es como dejar una tarea por escrito y decidir cuándo hacerla. En código, el trabajo concreto es la función que pasaste. Creating Effects

¿Para qué guardarlo como Effect?

Imagina que una tienda recibe la cantidad "2" desde un formulario. Cada pieza cuesta 25. Si la cantidad es válida, puede calcular el total. Si alguien escribe "dos", la tienda necesita saber por qué no pudo calcularlo. Effect deja mostrar ambos resultados posibles en el tipo:

Effect.Effect<number, InvalidQuantity>

number es lo que obtienes si sale bien. InvalidQuantity es el nombre que el ejemplo le da a la entrada inválida. El ejemplo devuelve 50 para "2" y produce InvalidQuantity para "dos". The Effect Type

Si quieres leer el interior de total

Effect.gen(function* () { … }) junta varios pasos en un solo Effect. Dentro, const quantity = yield* parseQuantity(input) pide que se ejecute el paso que convierte y comprueba la cantidad. Si obtiene un número, lo guarda en quantity y pasa a la línea siguiente. Si ese paso falla, el programa termina con ese fallo antes de imprimir la cantidad. Building Pipelines
