Fundamentos Worker y R2 Estado y plan Referencia

Leer un plan antes de desplegar

Alchemy compara los recursos declarados con su registro del último despliegue. El resultado es un plan que indica qué se creará, actualizará, reemplazará, eliminará o quedará igual.

Qué guarda el estado

El estado guarda el vínculo entre el identificador lógico en el código, como Notes, y la instancia que administra Alchemy. Incluye propiedades de entrada, valores devueltos y el estado del ciclo de vida. En el ejemplo se escribe bajo .alchemy/. El contenido de note.txt vive en R2. El estado pertenece a un stage, el nombre del entorno que usa el stack para aislar ejecuciones como dev y prod.

Cómo aplica el plan

El provider usa diff para decidir si un cambio de propiedades puede aplicarse a la misma instancia. Al crear o actualizar, reconcile observa el recurso y hace las llamadas necesarias para alcanzar la configuración deseada. Si un recurso debe desaparecer, delete se ocupa de borrarlo. Un reemplazo implica una instancia nueva y el retiro de la anterior. Si un paso falla, examina el error y el siguiente plan antes de reintentar.

En el primer arranque local, el plan del ejemplo muestra dos recursos y un cambio de binding. Aunque el plan lista Api primero, el registro de ejecución muestra que Alchemy empieza por Notes.

Plan: 2 to create, 1 binding changes
[Api] create (local)
[Api/Notes] create
[Notes] create (local)

Un cambio manual en el panel del proveedor puede dejar la configuración real distinta de la registrada. A eso se le llama drift. Un plan calculado a partir del estado guardado por sí solo no prueba que el proveedor siga exactamente como quedó registrado. Alchemy documenta el comando drift para consultar esa diferencia.

Modificas un dato mediante el Worker. El código del stack y las propiedades del bucket siguen iguales.

Cambiar el ID lógico de Notes a Memo en la llamada a Bucket

Alchemy puede planear un bucket nuevo y retirar el anterior. El nombre de la variable TypeScript da igual para la identidad. Si la intención es conservar la instancia, estudia renamedFrom y revisa el plan.

Comandos para un entorno en la nube

Estos comandos se ejecutan desde el directorio del ejemplo. Un despliegue real necesita un perfil de Cloudflare, R2 habilitado y los permisos aplicables. Revisa la cuenta, el stage y el plan antes de aceptar cambios, especialmente al destruir un stack.

npx alchemy profile edit --add Cloudflare
npx alchemy plan --stage lab-cloud
npx alchemy deploy --stage lab-cloud
npx alchemy destroy --stage lab-cloud
